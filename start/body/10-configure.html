Prepare your server

Jump to: Configuring Apache, Lighttpd, nginx and others

Every website needs a server to host it, and the NSI engine is implemented as a Perl CGI script - once the gold standard of the server-side dynamic web, which means it can run on just about anything.

There are, however, some caveats to consider:

  • Most web servers out of the box don't execute CGI just anywhere. Older servers especially relegate dynamic scripts to special areas like cgi-bin/. Like modern PHP, Python, JavaScript and other web frameworks, you might need some one-time configuration before deploying NSI.
  • Some web servers don't execute CGI at all. CGI was once the gold standard, but some popular modern web servers, particularly nginx and Caddy, have since dropped official support, though you can bring it back with a wrapper like fcgiwrap. We recommend Apache or Lighttpd.
  • NSI is tailored to POSIX, or Unix-like environments. It's likely the engine will run on Windows or other platforms, but it hasn't been tested, and a number of features (especially executable script fragments) are likely to break without adaptation. Expect full advertised functionality only under systems like Linux, macOS or real Unix.
  • If you're deploying NSI to an especially old target: this engine has thus far been tested as far back as Perl 5.005_03, released in 1999. It might work fine on older versions... or it might not.
